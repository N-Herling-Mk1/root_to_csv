------------------------------------------------------------------------------
LOCKED DECISIONS
------------------------------------------------------------------------------
  1. Six branch bins (names and semantics are FIXED):
       scalar       ndim 1                       -> straight through
       vec1         ndim 2, length 1 everywhere  -> collapsed via [:, 0]
       jagged       ndim 2, variable length      -> exploded + padded
       jagged_deep  ndim > 2                     -> parquet only, never CSV
       empty        max_len 0 everywhere         -> skipped
       unreadable   uproot cannot decode         -> recorded by NAME + reason
                                                    only; that is good enough
  2. Canonical parquet = bulk storage. Lists stay lists, jagged_deep intact.
     CSVs are disposable views regenerable without re-touching ROOT.
  3. Three layers, three scripts. Layers 1-2 are the pipeline; layer 3 is
     optional post-processing and nothing depends on it:
       Layer 1  scan.py     census every struct -> parquet + manifest.json
                            + manifest.txt
       Layer 2  convert.py  ROOT -> flat CSV
                  2a QUICK      no pre-scan; scan+flatten one shot, default
                                policies == events.root behavior (hard
                                structs removed from CSV)
                  2b FROM-SCAN  manifest-driven; honors per-branch policy
                                edits in manifest.json; reads canonical
                                parquet, never re-reads ROOT
       Layer 3  dropfilter.py  OPTIONAL. Removes whole branches named in
                            drop_list.txt -> filtered CSV + drop report.
                            Reads flat.csv + manifest.json ONLY; never
                            opens ROOT, never reads or writes the parquet,
                            never edits flat.csv or the manifests. Pure
                            stdlib -- no uproot, so it runs on a
                            copied-down scan dir.
  4. Jagged policies (per branch, "policy" field in manifest.json):
       pad_max (default) | first:N | drop
  5. BASE-POLICY pad flag: -999 (numeric; jagged-derived columns stay
     numeric dtype). Chosen over -99/-255 as the entrenched HEP sentinel,
     far from physical ranges. --fill x restores the legacy events.root
     'x' sentinel (byte-parity with the original CSVs); --fill nan pads
     NaN; --fill <number> pads that number. NOTE: default output now
     DIVERGES from the April events.root CSVs unless --fill x is passed.
  6. Tree resolution: --tree, else auto-detect = the TTree/RNTuple with the
     most entries (fastframe files carry reco/truth/etc, not 'analysis').
     Both TTree and RNTuple read paths supported.
  7. --tag KEY=VALUE integer columns stamped on every row (kept from
     flatten_events).
  8. Headless-first: pip-only deps (uproot awkward pandas numpy pyarrow),
     argparse CLI, custom \r progress bars on every pass, zero display
     requirements. Deploy = git clone + pip install -r requirements.txt.
  9. Any served pages bind 127.0.0.1 ONLY; ssh tunnel is the only door.
 10. LAYER-3 FILTERING is BY NAME, never by structure. drop_list.txt holds
     BRANCH names (trackID_pt), never CSV column names (trackID_pt_0).
     manifest.json is the lookup table that expands branch -> columns; it is
     never the policy. Deliberately orthogonal to the six bins: a branch is
     dropped because it is listed, not because of which bin it landed in.
     Structure-based rules (e.g. "drop everything jagged") are NOT in scope.
 11. LAYER-3 FAILURE MODE is LOUD. A drop-list name matching no branch in
     manifest.json is a hard error: nothing written, non-zero exit, offending
     line numbers printed (--allow-unmatched to downgrade). A resolved-but-
     absent column, or a manifest width disagreeing with the data, is
     reported as an integrity failure. Rationale: a silent skip yields a CSV
     wider than the operator believes, which corrupts everything downstream.
     An ABSENT drop list is the one quiet case - that is a clean no-op at
     exit 0, because layer 3 is optional by design.
 12. MASTER COPY: canonical.parquet keeps EVERY branch, including every one
     layer 3 removes. Only the CSV is filtered. Re-filtering with an edited
     list must never require a re-scan, a re-convert, or the ROOT file.
 13. LAYER 3 FILTERS flat.csv, NOT the parquet. Per decision 2 the parquet
     keeps lists as lists: a jagged branch is ONE list-valued column there,
     not its `fanout` exploded CSV columns. Filtering the parquet would
     remove 1 column per branch and leave list cells behind. Re-exploding it
     inside layer 3 would duplicate layer 2's padding/fill/policy logic --
     rejected. (Found in vetting, 2026-09-11: the parquet path reported
     202 -> 85 columns and 117 width mismatches.)
 14. COLUMN WIDTH comes from the branch's POLICY, never from `fanout`.
     `fanout` is the base-policy width frozen at scan time; an edited
     "first:N" policy makes the real CSV narrower. dropfilter.py carries a
     local copy of convert.py::resolve_policy (it cannot import it --
     convert -> common -> uproot, and layer 3 must stay uproot-free) plus a
     drift guard that cross-checks the two whenever convert.py IS
     importable.
 15. LAYER 3 VERIFIES ITS OWN OUTPUT. After every write it re-reads the file
     produced and asserts: column count == promised, row count == source
     (filtering never changes rows), all rows equal width, no dropped column
     present, and every input unchanged (size+mtime, or md5 with
     --verify-hash). A failure exits 4 and says the output is suspect. The
     operator must not have to run head/wc/md5sum by hand to learn whether
     the tool did what it said.
 16. LAYER-3 OUTPUT IS NEVER OVERWRITTEN. The filtered CSV is auto-named
     MM_DD_YY_HHMMSS_filtered.csv from local clock time; --out PATH overrides.
     The drop report takes the same base name so the pair is unambiguous.
     Rationale: the drop list is expected to churn, so re-runs are the normal
     case and each one's result must survive for comparison. Cost: the scan
     dir accumulates runs — pruning is the operator's call, never the tool's.
 17. NEVER CALL .tell() ON A HANDLE A csv.reader IS CONSUMING. Python disables
     tell() once next() has been called on a file object; the call raises
     "OSError: telling position disabled by next() call". Size progress bars
     by ROW COUNT, not by byte offset. (Field failure 2026-09-12: the writer
     called tell() every 500th row, so the 423-row vet file never reached the
     faulty branch and every local test passed. Any test set whose row count
     is below the progress interval cannot exercise the progress path — vet
     files must exceed it.)
     Port/tunnel hygiene checklist lives in README ("before you log out").

KNOWN LIMITS / ROADMAP  (deliberately deferred)
------------------------------------------------------------------------------
  - Pass 1 caches all branch arrays in RAM (transplanted behavior). Fine
    for sample-scale files; big files want bigmem3 or a future chunked mode.
  - CSV assembled as one in-RAM DataFrame; chunked CSV writes are roadmap.
  - pad_p99 / overflow-flag policy: roadmap (first:N covers most of it).
  - Outlier fan-out warning: manifest exposes len_med/len_p95/len_max so
    column explosions are visible BEFORE committing to a flatten.
