IGNORED BRANCHES — the default drop list

Step 5 removes these branches from a copy of the CSV. They stay in flat.csv and in the parquet. Nothing here is permanent — the list is a plain text file you edit.

✎ THE FILE TO EDIT — drop_list.txt Repo root, beside scan.py and convert.py. Plain text, one branch name per line. Lines starting with # are comments and are skipped on read, as are blank lines — so you can annotate freely and comment a name out instead of deleting it.

It ships with the repo, so step 5 finds it from any working directory — no path needed. If you want a different list for one job, put a drop_list.txt in the scan directory or in the directory you run from; either wins over the repo’s copy. --drop-file overrides all three.

Delete this file and step 5 becomes a clean no-op: steps 1–4 still run and still produce flat.csv. Nothing about the list is load-bearing.

THE RULES — HOW A LINE IS READ

write thismeaning
trackID_pta branch name. Matched against manifest.json, which expands it to every column it produced — trackID_pt_0 through trackID_pt_486 on the vet file. One line, 487 columns gone.
trackID_pt_0✗ a column name. Not accepted — this is an error, not a near-miss.
caloCluster_*a glob, resolved against manifest branch names. Convenient, but opaque in review — prefer explicit names for anything that encodes a decision.
# jets — not used downstreama comment. Skipped. Inline after a name works too.
(a name that matches nothing)✗ hard error. Nothing is written, the run exits non-zero, and the offending line numbers are printed. A typo cannot quietly hand you a wider CSV than you asked for.
Careful with prefixes: trackID_eta and track_eta_NOSYS are different families. Matching is anchored on the whole branch name, so listing one never touches the other — but a sloppy glob like track* eats both.

The run checks itself. After writing, the tool re-opens the file it just made and verifies the column count, the row count against the source, that every row is the same width, that no dropped column leaked through, and that flat.csv, the parquet and the manifests are all untouched. Any failure exits non-zero and says the output is suspect — you should not have to run head, wc and md5sum yourself to find out.
Changed your mind? Edit the list and re-run dropfilter.py. It reads flat.csv and writes a new file, so there is no re-scan, no re-convert, and neither the ROOT file nor uproot is needed — you can do it on your laptop from a copied-down scan directory.
